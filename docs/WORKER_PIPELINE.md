# Пайплайн воркера (Worker Pipeline)

Пошаговое описание обработки одного входящего сообщения: от очереди до постановки ответа в outgoing.

---

## Вход

- **IncomingMessage**: `chat_id`, `user_id`, `text`, `message_id`, `voice_file_id` (опционально).
- Если пришёл голос без текста: на текущем этапе можно положить в очередь с пустым `text` и пометкой `voice_file_id`; транскрипция — отдельный шаг (Gateway или первый шаг воркера). В прототипе можно временно отвечать «Пока принимаю только текст».

---

## Шаги пайплайна

### Шаг 0. Подготовка (опционально)

- **Транскрипция**: если `voice_file_id` задан и `text` пустой — скачать голосовой файл, распознать речь (Telegram Speech-to-Text или внешний API), записать результат в `text`. При ошибке — положить в outgoing сообщение «Не удалось распознать голос» и выйти.
- Далее везде работаем с непустым `text` (или явно обрабатываем пустой как «нет текста»).

### Шаг 1. Классификация: новая тема или продолжение

- **Вход**: `user_id`, `text`, контекст (последние узлы пользователя из графа, опционально последние N сообщений из кэша).
- **Действие**: вызов ИИ (или эвристика на старте) с промптом вида: «Пользователь написал: “…”. Это новая тема или продолжение предыдущей мысли? Если продолжение — укажи id узла-родителя.»
- **Выход**:
  - `is_new_topic: bool`
  - `parent_node_id: str | None` — к какому узлу привязать ребро (если продолжение).
- При отсутствии графа/узлов считаем всё новой темой; `parent_node_id = None`.

### Шаг 2. Обновление графа мыслей

- **Вход**: `user_id`, `text`, `parent_node_id`, `message_id` (для трассировки).
- **Действие**:
  - Создать новый узел: `content = text` (или нормализованный/очищенный текст), `user_id`, `source_message_id`, `created_at`, `updated_at`.
  - Если `parent_node_id` задан — создать ребро `(parent_node_id → new_node_id, edge_type=continuation)`; иначе узел без входящего ребра (корень или первая мысль).
- **Выход**: `new_node_id` — id созданного узла (для RAG и при необходимости для ответа).

### Шаг 3. Обновление RAG

- **Вход**: `user_id`, `new_node_id`, текст для индексации (например, `content` узла или краткое обобщение).
- **Действие**:
  - Построить эмбеддинг текста.
  - Добавить в RAG-хранилище чанк: `user_id`, `text`, `embedding`, `source_node_id = new_node_id`, `id` (уникальный).
- **Выход**: успех/ошибка; при ошибке — логировать, не падать (ответ пользователю всё равно формируем).

### Шаг 4. Генерация ответа (агент)

- **Вход**: `user_id`, `text` (исходный запрос), контекст из RAG (топ-k чанков по запросу), опционально контекст из графа (последние узлы, соседи).
- **Действие**: вызов агента «универсальный помощник» (см. [AGENTS.md](AGENTS.md)): промпт + контекст RAG/графа → ответ ИИ.
- **Выход**: строка `reply_text` для пользователя.

### Шаг 5. Постановка ответа в очередь

- **Вход**: `chat_id`, `reply_text`, `message_id` (для reply_to_message_id).
- **Действие**: сформировать **OutgoingMessage**(chat_id, text=reply_text, reply_to_message_id=message_id), положить в очередь **outgoing**.

---

## Обработка ошибок

- **Шаг 1 (ИИ классификация)**: при сбое — считать новую темой, `parent_node_id = None`.
- **Шаг 2 (граф)**: при сбое — логировать, попытаться вернуть ответ пользователю с сообщением об ошибке и не класть в RAG некорректные данные.
- **Шаг 3 (RAG)**: при сбое — не прерывать пайплайн; ответ без RAG-контекста (только запрос пользователя).
- **Шаг 4 (ИИ ответ)**: при сбое — положить в outgoing сообщение «Временная ошибка, попробуй позже» (или повторить один раз).
- **Шаг 5**: при сбое записи в очередь — повтор по политике воркера (retry).

---

## Порядок реализации

1. Реализовать шаги 2 и 3 в упрощённом виде: всегда новая тема (без ИИ на шаге 1), один узел = один чанк в RAG.
2. Подключить шаг 4 с реальным ИИ и простым промптом (запрос + топ-k из RAG).
3. Добавить шаг 1 (ИИ или эвристика «последний узел = родитель») и рёбра в графе.
4. При необходимости — шаг 0 (транскрипция голоса).

Контракт первого агента (универсальный помощник): [AGENTS.md](AGENTS.md).
